# M2c independent design review

**Approve the bounded direction with three explicit refinements before handoff.** Reviewed M2c design and immutable504c845 context-time audit, plus current ClaimStore invalidation/history and source ignore/reopen call paths. M1d's proposed snapshot seam is not assumed implemented. No code changes, models or tests.

## 1. Distinguish rendered-field lineage from withdrawal continuity

The proposed signature correctly binds rendered semantics and primary source times, but must not imply that a matching projection proves uninterrupted permission. A source can be ignored and reopened with the same body/date/reference; both projections match. Current public ignore/reopen routes call claims.invalidate_source and leave affected claims disputed, which M2c must preserve. A snapshot's current generation must never be copied into an old acceptance/history entry to make it match.

For new lineage, preferably capture a separate validity binding covering source ID+withdrawal generation for **every required source in the transitive claim graph**, not just the rendered primary. Compare against newly read generations on history/publication validation; do not hash ordinary archive/consolidated/produced changes. This records the source state actually supplied, not a ClaimStore reauthorization commitment. A generation mismatch invalidates old derived history. It does not grant fresh retrieval permission, repair legacy acceptance, or replace existing claim status/evidence rules. If generation continuity is deliberately left outside M2c, say so explicitly and keep regression coverage proving all supported ignore/reopen routes invalidate claims before reuse; do not call the new signature source-authorization proof. Missing snapshot/generation data is unavailable, never an implicit generation0 baseline.

## 2. Freeze recorder expectations independently before execution

“Immutable fixture expectations/captured source snapshot” should mean an immutable manifest prepared before invoking the Agent/provider, from the synthetic fixture's authoritative rows and declared test dates—not the production KnowledgeInputBuild/projection/signature output, nor a later read after completion. Implement expected v3 field construction in the verifier independently and compare exact fields, types, nested source IDs and canonical timestamps. Preserve raw requests and expected manifest/hash. A mutation test must distinguish what was actually sent from what became current later: the former can be correctly attributed even when the production turn is then invalidated.

Keep strict v2 historical parsing, but v2 must not satisfy metadata declaring v3 time/semantic fields. Unknown keys/version, mismatched value/date/source and unreported rows fail integrity. Normalize equivalent offsets only in the explicitly specified timestamp canonicalizer, not arbitrary strings/whole payloads. Test the normalizer independently with hard-coded expected instants so production and recorder cannot share the same mistaken fallback. Old reference_context and reference_identity_context requests must retain exact bytes/order/meaning; record knowledge payload version in new Agent reports rather than silently relabelling historical files.

## 3. Make build budgets and omission accounting exact

Approve8KiB UTF-8 per full JSON row and32KiB total prefixed/newline-delimited knowledge rows, at most five rendered rows. Use the actual serialized representation; multibyte characters and escaping count. Exclude fixed explanatory text only if the metadata/documentation explicitly says the limit is data rows, not the whole prompt. Reject a whole oversized row; only delivered rows enter ContextItem and lineage.

Choose explicit distinct-source and claim traversal limits for the whole build/revalidation, with no eviction-and-reload workaround. Reusing M1d's128-source-node ceiling is reasonable only as a separately documented M2c budget; don't consume SelfModel producer slots by accident. When skipping an oversized row, consider remaining already-bounded candidates until five fit; do not stop at the first five candidates and claim continuation. payload_omitted counts only candidates actually examined and omitted for bytes, not unseen recall loss. Source/evidence checks must stay complete within the cap; cap exhaustion makes a candidate unavailable, never partially checked.

## Other rulings

- The v3 projection is minimal and justified: canonical predicate/value/claim acceptance time/valid interval plus primary original event/import dates and identity. Explicit null event time is essential; recorded_at is not occurrence. Primary means first stored evidence, not earliest or exclusive evidence. Preserve future occurrence as a possible planned event, independently of claim validity. Use [valid_from,valid_until) and aware canonical UTC.
- One pure projection from exact frozen checked objects should feed prompt/API/signature. Keep the signature free of query selection reason and unrelated mutable source fields. ClaimStore semantic schema need not change merely to render existing immutable fields.
- Keep M1d low-level snapshot/physical source/quote helpers separate from SelfModel producer authorization. Re-read final seam and verify canonical row/head correspondence before adoption. No reassessment or support-CAS methods belong in M2c.
- Knowledge lineage v2 must require exact equality between its root-ID set and signature-map keys, with selected items a matching subset, no duplicate IDs and all-prior-turn union. Nonempty v1 lineage is unknown. Prefer one conservative reset for all v1; accepting strictly validated empty v1 is also safe if explicitly tested. Never replace an old root signature when it differs.
- Capture and revalidation use separate caches. Verify all actual/scoped/injected Agent construction paths, pre/post-provider/error/tool boundaries and approval resolution. Current cards hide a changed captured item; they must not display later timestamps as if the old provider saw them. Preserve historical transcript and M1c/M1d qualifiers.
- The proposed optimistic publication boundary is honest. Metadata changed inside a provider call can invalidate output, but cannot erase input already sent; no atomic model/source claim. Local-only knowledge egress remains independent of signature matching.

Minimum acceptance remains actual fake-provider semantics/time fields, null/offset/interval controls, primary-vs-secondary source distinction, changed source dates/ref with unchanged claim revision, capture races and stale returned tool calls, same-Agent/reload/current cards, unchanged post-reset history, local-to-external exclusion, huge UTF-8 rows, explicit omissions and unchanged reference requests. Add ignore→reopen between turns and secondary-ancestor generation controls according to refinement1. No live model run is needed to establish payload correctness. Restore journals, legacy ClaimStore reauthorization and general answer qualification remain separate work.
