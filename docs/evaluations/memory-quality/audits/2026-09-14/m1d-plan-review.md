Existing code does not already supply a generic Kingfisher SelfModel review page.

## Proposed exact API slice

- GET `/api/v1/assertions/support-review?after=...&limit=...`: bounded keyset pagination over eligible recognized accepted legacy assertion IDs; never newest-N evidence lookup. Return statement, recorded evidence date, support state and stable assertion ID. Page through old records; no source migration/reapproval during listing.
- POST `/api/v1/assertions/{id}/support-reassessment/preview`: read-only computation despite POST; return exact existing statement/kind and original factual date, producer ID, every required quote and source identity/version, current eligibility with generic blocked reasons, preview token and expiry. Blocked previews have no enabled submit capability.
- POST `/api/v1/assertions/{id}/support-reassessment`: accepts only preview_token plus explicit confirmed=true; does NOT accept arbitrary client-supplied evidence, generation, support, statement, timestamps, sensitivity or source IDs. Under the current mutation lock, re-resolve authoritative assertion, producer, all evidence, M1c ancestry and permissions; reject stale/expired token with 409 and no writes. Recompute full preview binding, then write typed support and audit.

Token binds assertion ID+full fingerprint, accepted producer ID+canonical evidence fingerprint/state, all source IDs/digests/metadata/head/generations, effective support/privacy mode and schema version. A hash is a stale-preview detector, not permission; authenticated explicit submission is still required. Use a server-issued expiring token (or existing preview mechanism with equivalent binding); do not accept a token copied to a different assertion. The token must cover the complete evidence set, including secondary evidence and duplicate/conflicting producers. Hidden/exhausted evidence makes preview blocked; never authorize only what fit the displayed excerpt.

On success do not call confirm(), record(), proposal.accept(), episode.reopen() or mark_consolidated(). Preserve statement, kind, source provenance, recorded_at, last_confirmed_at, valid_from, expires_at, confidence, status/status_changed_at and existing domain structured data. Add a separate support-reviewed time/token lineage if needed; it is not evidence_date. Status retired/redacted/expired/future must not be reactivated. Explicitly choose whether historical-but-ineligible records can receive archival support-only updates; smallest slice rejects non-ACTIVE records and requires independent existing domain paths for other changes. An outdated ACTIVE statement can have supported evidence and still remain outdated by currency rules; show this distinction in preview and success copy.

## Concrete unsafe edge in UI reuse

`ProfileSource` currently defaults allowIgnore=true. Even `allowIgnore={false}` does not disable reopening: its ignored-source branch always exposes “Quelle wieder zulassen”. `ClaimEvidence` uses ProfileSource with defaults. Therefore dropping either component unchanged into reassessment would introduce source permission-changing actions inside what the plan says is evidence-only review. Add an explicit read-only/action mode suppressing BOTH ignore and reopen, or render read-only original excerpts directly. Existing source permission UI elsewhere can remain available as a separate deliberate operation; reassessment neither invokes it nor presumes consent from its existence.

## Additional contract checks before implementation

1. Reassessment may approve the same original evidence under the CURRENT non-ignored generation after a separate explicit source reopen. It must never select replacement head text or changed quotations automatically. New evidence for a changed factual assertion is a new proposal/correction, not this endpoint.
2. Typed support must not become writable via generic RecordIn or loose imported structured data. Imported support remains data subject to local producer/source/generation validation; hash equality or export provenance does not recreate missing authorization. Restore quarantine is still explicitly outside this patch.
3. Episode/proposal sensitivity is not user consent to cloud transport; support stays local-only regardless of reassessment. Preview is local UI, not a model call. Include ancestry qualification/privacy from M1c in binding and revalidation.
4. The dedicated support mutation must preserve the backend append-only content contract. `ensure_content_unchanged` protects original content/provenance but does not itself govern a new field. Make allowable support replacement explicit; redact removes quote-bearing support, and repeated same-token submission must be idempotent or return a clean stale/already-applied result without rewriting factual dates.
5. If evidence changes between preview and submit, or between validation and write across DBs, fail closed. Existing conversation_lock does not automatically cover every assertion mutation: verify confirm/retract/redact handlers and all relevant source writers use the same serialization or perform final version validation. Do not infer atomicity from one route holding a lock.

Repeat with stale preview, second-source ignore, source reopen after preview, ancestor sensitivity escalation, duplicate producer, expired assertion and replayed token. Verify source buttons cannot be triggered from reassessment and no model tool exists for this operation. Include snapshot/export/backend round-trip and redact removal of new quotes. Episode/source restore limitations remain explicitly open.
