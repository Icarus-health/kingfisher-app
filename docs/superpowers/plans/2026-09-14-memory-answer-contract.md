# M3 first step: evidence-bounded memory answer contract

Execute only after current M1/M1b correctness repairs, M2 candidate retrieval and
preservation of canonical entity references in actual context. Source-only reference
context in the initial baseline does not isolate identity metadata completeness.
Use superpowers:subagent-driven-development. User authorizes local completion;
no cloud export, new downloads, model authority or automatic acceptance changes.

## Evidence driving this work

The preserved 72 baseline attempts on identical code show repeated unsupported
negative conclusions from missing evidence, conflation of distinct same-name people,
unnecessary incorrect weekdays, missing citations and invented user-goal attribution.
Reference context proves several failures persist when expected evidence is present.
The prompt's suggested goal-preface is a plausible contributor; causation has not yet
been isolated by an otherwise identical prompt comparison.

## Narrow implementation

Revise the existing answer instructions, preserving tool/approval boundaries:
- Attribute the actual source/type. Call something a user goal/preference only when
  the evidence explicitly says so; do not add a stock goal-preface to observations.
- Missing information is unknown, never automatically false, absent, completed or sent.
- Distinct entity references remain distinct. Ambiguous person/topic requests require
  a short concrete choice using the supplied contexts; do not invent an identity merge.
- Include source references for material memory claims; preserve explicit date/timezone
  when answering a calendar question. Do not add an unverified derived weekday.
- Answer briefly at the required depth. A clarification should enable the next step,
  not require a full restatement or expose irrelevant personal context.

Do not add string-based automatic grading as a substitute for semantic review, or
regex templates that merely memorize the existing six scenarios. Do not change the
provider/model/defaults while isolating the prompt change. Capture the actual prompt
and configuration hash with every new diagnostic attempt.

## Evaluation

- Freeze pre/post commits; run the same prepared-memory development cases through
  actual Agent and reference modes using existing local models, preserving every attempt.
- Compare one factor at a time; actual retrieval/candidate changes must be recorded,
  not silently attributed to the prompt. Before/after times are diagnostic only.
- Add independent counterexamples before inspecting model outputs: clear single identity,
  explicit sent/not-sent/unknown state, confirmed current goal versus exploratory thought,
  corrected date, genuinely ambiguous and unambiguous topic. Keep required/forbidden
  semantics source-authored, with positive controls to detect indiscriminate abstention.
- Review responses against sources and original question. Distinguish severe factual
  errors, answer-contract omissions, useful clarification and conservative refusal.
- Any remaining known severe defect prevents qualifying the affected answer class.
  Passing this small collection does not meet the broader held-out/human/latency gate.
- Preserve explicit sources and source access during user review. No model-generated
  confidence can grant source rights, merge people or create user commitments.

No claim of AGI, zero errors, complete world awareness or general model qualification.
The larger roadmap evaluation sizes and human acceptance remain separate requirements.
