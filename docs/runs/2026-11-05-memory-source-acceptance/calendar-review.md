## Important

1. **Retry permanently loses a cancellation after a head-update failure** · `sidecar/icarus_memory/calendar_memory.py:337`–342, `sidecar/icarus_memory/source_versions.py:45`–51. `track_source` invalidates the former head and ignores it before updating the head pointer. The new guard interprets the ignored, unmarked state as a user exclusion even when the preceding source transition caused it. I injected a single `EpisodeError` at `advance_source_head` after a real cancellation read, restored the method, and retried. The retry reported `ausgeschlossen=1`. The original ID stayed as an ignored head and the cancellation stayed unavailable. Preserve the distinction between a user exclusion and a pending source transition, and cover the failed advance and successful retry in a regression test.

2. **A malformed detached occurrence can withdraw valid historical evidence by omission** · `sidecar/icarus_memory/connectors/calendar.py:1062`–1064, 1168–1173. A detached active VEVENT with a parseable `RECURRENCE-ID` and invalid `DTSTART` is discarded before the caller checks for invalid dates. With a healthy neighboring VEVENT in the same framed feed, `complete` stays true. I synced a valid detached occurrence and its neighbor, then replayed the occurrence with `DTSTART:invalid` and the neighbor unchanged. The real subscription job reported one withdrawal and the prior occurrence became ignored. Mark a failed detached parse incomplete while continuing to read healthy rows. Distinguish that condition from legitimate out-of-window events.

3. **A publication delta can withdraw an unlisted neighbor** · `sidecar/icarus_memory/connectors/calendar.py:1137`–1139. The code treats `METHOD:PUBLISH` as proof of a complete section. The method identifies a publication and does not establish full coverage of the calendar. I synced two current events, then sent a fully framed HTTP 200 `METHOD:PUBLISH` body containing just one unchanged event. The read reported `complete=True` and withdrew the unlisted event. Allow its positive evidence and suppress absence-based withdrawal unless the source provides independent snapshot coverage.

4. **The first unchanged read after upgrade can invalidate existing evidence** · `sidecar/icarus_memory/calendar_memory.py:330`–359, 374–378. The old digest fast path now also requires equal revision marks. A saved, unmarked active head and the exact same ICS bytes with `SEQUENCE:0` register a new metadata fingerprint. I recorded the pre-fix shape through the display projection and replayed the same bytes through the memory projection. The replay reported `geaendert=1`, changed the episode ID despite an identical body digest, and made the original snapshot ineligible. The shared version path also disputes claims that cite it. Preserve existing support while establishing revision metadata for an otherwise unchanged head.

5. **A series cancellation discards the explicit cancellation for a detached occurrence** · `sidecar/icarus_memory/connectors/calendar.py:1019`–1023. With a cancelled RRULE master, the projection always builds each detached cancellation from the master, including when that detached VEVENT explicitly cancels itself. A synthetic series with a master cancellation note and a distinct detached cancellation note and DTSTAMP returned the master note and no timestamp for the detached identity. The same path clears a detached DTSTART when supplied. Keep the actual detached cancellation fields and use the master projection when the occurrence has no explicit cancellation of its own.

6. **Sparse master cancellation leaves current, already known occurrences active** · `sidecar/icarus_memory/connectors/calendar.py:1073`–1081, `sidecar/icarus_memory/calendar_memory.py:306`–319. This is the author's disclosed scope gap. I synced a two-occurrence series and a newer sparse `METHOD:CANCEL` master with its UID and sequence, without an RRULE or DTSTART. The job created a separate cancellation head for the raw UID and both prior occurrence heads remained current. The safeguard against guessing a recurrence window is sound. Previously recorded occurrences with a verified raw-UID link are different from hypothetical occurrences and can be targeted with an explicit policy for competing revisions. If sparse masters are deferred, describe standalone and explicitly projected occurrence coverage and keep whole-series cancellation open.

## Boundaries and evidence

- The known legacy ambiguity is real. A raw UID ending in the recurrence suffix and a projected occurrence can share the same pre-fix head key. The patch conservatively preserves the unmarked head on cancellation, records an error, and suppresses omission for that read. This leaves some legitimate legacy occurrence cancellations unresolved. Resolving historical identity requires reliable additional evidence.
- The package's tests exercise the positive standalone path, idempotence, restoration, scoped identity, independent document support, display, ordinary and moved recurrence cases, and several incomplete reads. The author's report states 224 passed and three localhost TLS cases deselected. I did not rerun that suite. I ran six focused offline counterexamples using synthetic ICS and temporary stores, including in-process HTTP for the four calendar job cases. I observed the outcomes described above.
- Shared versioning invalidates direct claim support and its dependents. Native UI behavior, live provider responses, runtime CI, downstream generated project views and prior-conversation readback, the frozen answer benchmark, and release acceptance remain unverified. A separately created document control establishes that an unrelated source head survives. It does not establish actual PDF intake and answer quality.
