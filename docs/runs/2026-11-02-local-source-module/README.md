# First controlled local source module — work in progress

## Scope

One explicit question about one selected current original, through pinned DeepSeek Harness, the canonical memory/skill broker and the positively verified local Qwen9B provider. The result is an unverified draft with actual original-read receipts and partial-read coverage. It cannot create tasks, modify confirmed memory or acquire extra sources, tools, providers or permissions.

This checkout implements the controller, authenticated routes, controlled worker/gateway, source-view action and native setup UI. It is **not activated in the personal app**. Native cache preparation, lifecycle orchestration, final exact-build checks and actual native-window acceptance are still being completed. The installed stable backend is 1.0.42.

## Verified boundaries

- Bounded ephemeral reviews/jobs, explicit source fingerprint and consent, repeat-safe admission, canonical source/skill/provider/runtime currentness, cancellation and physically retained inference occupancy.
- The new `selected_original` tool opens only the granted original's exact bounded prefix, including for generic questions with no literal search term. An empty read supplies no positive evidence.
- A draft without any positive original-read receipt is withheld. Coverage reports characters actually opened; it is not a factual-verification score.
- Backup pauses invalidate unstarted/in-flight reviews and wait for actual execution exit. Update/restore revoke first. Independent review found and verified the repair of a completed-replay race across a maintenance pause.
- Independent server review exercised authentication before restore-body reads, bounded body replay, wrong/invalid restore requests, actual model callback drain and exact administrative-path exclusion. No known finding remains in that reviewed server slice.
