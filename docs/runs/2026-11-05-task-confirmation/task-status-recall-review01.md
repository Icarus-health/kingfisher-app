#### Important (Should Fix)

**I1 — Restoring a task can launder a withdrawn mail-derived completion into an unknown-origin completion.** sidecar/icarus_memory/tasks.py:878–893 restores the exact prior document, including the completion reason and time. Recall treats `auto_restored` as a new boundary (:1023–1030), but only recognizes mail provenance when that boundary itself is `post_completed` (:1040–1054). The new proof therefore omits the mail stamp (task_status_answers.py:85–104), even as the renderer still displays the restored completion time and exposes the link (:210–225, :246–253). The ordinary automatic-task undo service invokes this restore (aufgaben_von_selbst.py:416–440). In a focused reproduction using real temporary TaskStore and EpisodeStore instances, a mail-completed automatic task showed the mail basis initially. After removal, restore and completion-mail withdrawal, a fresh lookup showed the same date/time, “Wer die Erledigung veranlasst hat, ist nicht bekannt” and an active link. Its pre-restore reply correctly stayed invalid. Treat the restore as a fresh revision while preserving or independently validating the saved completion’s provenance. If the store cannot prove that origin within the bound, withhold the projection; do not trust a bare reason or promote a pre-restore confirmation into a new receipt. Add a restore-plus-withdrawal regression separate from the existing replacement-ID case (sidecar/tests/test_task_status_recall.py:436–452).

**I2 — Old typed answers can revive after archival and re-admission, including via an attachment’s parent.** sidecar/icarus_memory/source_snapshot.py:29–37, :57–59, :71–82 rejects archive in strict mode but fingerprints the existing generation; neither `archive_before` nor `mark_consolidated` advances it (episodes.py:1351–1371, :1434–1453, :2316–2336). Re-consolidation is an existing store operation and a real call path can mark a supporting episode consolidated when accepting a proposal (consolidation.py:480–484). In real temporary stores, the same saved task reference gave link/no link/link across archive and re-admission of its direct source, and independently across archive and re-consolidation of its mail parent with a newly produced synthetic assertion. No task mutation occurred. The existing parent archive case stops at denial, before readmission (sidecar/tests/test_task_status_recall.py:401–434). The task-specific fingerprint needs an incarnation that changes irreversibly across withdrawal/re-admission; prove this for both direct and parent support while leaving the existing default fingerprint bytes and claims alone. If the existing store has no suitable marker without a scope change, bring that specific choice back to the controller.
