# Prepared schema-20 installer — synthetic verification only

This directory contains a narrowly scoped, import-safe Python installer for Kingfisher revision `5621ec9e1f94ee40ea12485e128950d251211be4`. **The author did not run this installer against Docker, a live application, private data, or the network.** All 31 tests use synthetic files, fake Docker/System/HTTP, or local pure functions. Root independently repeated the same suite: `ROOT-GREEN.log` records 31 passed in 1.35 seconds. Root independently proved the package-check container's real tmpfs/cp behavior; that is separate evidence, not an installation claim.

The image is pinned to `sha256:72837cc0356954760e26aa1f9eb99713edc5287f598d7bd1a994f28a4298168f`. Native binary, Info.plist and Compose are backed up and must keep their supplied exact hashes; they are never replaced. The only live configuration change is the `KINGFISHER_IMAGE` line, after migration is independently proved. Every other byte of the env file is preserved. Compose's process environment excludes `KINGFISHER_*`, `ICARUS_*` and `LLM_API_KEY`, so shell variables cannot override that file. No model, cloud, import or schedule setting is activated.

## Files and invocation

- `orchestrator.py`: fixed image/volume/service lifecycle; CLI import has no actions.
- `data_proof.py`: standard-library, read-only evidence helper. No application/provider imports.
- `preflight.py`: **byte-identical** reviewed migration one-shot, SHA256 `19bc7ff195e760f277fcad4e80dd64f4dddc5ec36221243e613d1917194c54c8`. Its code was not edited.
- `test_orchestrator.py`: 31 portable synthetic checks, with the adjacent frozen preflight used solely for checksum validation. Requires pytest, no product checkout or Docker.
- `config.example.json`: metadata-only template. Real paths must be absolute; replace placeholders and review hashes. Credentials are read only from the existing env file at execution; never put them in this JSON.
- `manifest.json`: immutable file hashes of the reviewed helper artifacts and test logs. `root-config.json`, caches and any later real-install result are intentionally excluded from the reusable artifact.

Test with `python -m pytest -q test_orchestrator.py`. CLI without `--execute` only prints `not_executed`; it does not read the config or contact Docker. Actual invocation, by the already-authorized operator after independent review, is `python orchestrator.py --config /absolute/metadata.json --execute`.

`root-config.json` was metadata-checked against this schema; Root owns and supplies its installation paths/hashes. `image`, `image_id`, `version` and `volume` must equal the hardcoded target. App paths, env path, fresh backup directory, native/Compose/plist hashes, native probe path/hash, package checker path/hash, expected manifest path/hash and preflight path are required. Both storage reserves must be positive byte counts. `operator_exclusive_window=true` attests the maintenance window below; it is not a substitute for the active checks.

## State transitions and evidence

1. Check operator maintenance attestation, no running native/Kingfisher Compose process and no loaded Kingfisher LaunchAgent label; check image ID, package/manifest/native hashes, signature/probe, exact named volume identity and only the expected app as current writer. Package check uses a new-image Python one-shot with `--network none`, `--restart no`, no ports, and exactly `--tmpfs /data:rw,noexec,nosuid,size=1048576`. This explicitly overrides the image's declared `VOLUME /data`; it never mounts the user's data. Scripts are copied into existing `/tmp/` with Docker create/cp/start, never host bind mounts.
2. Check storage before stopping: host free space must cover the complete recursive cold tree plus the app/env backup and explicit host reserve. Docker-volume free space must cover three times the root product snapshot files (excluding existing nested snapshots and the operational recovery DB) plus its explicit reserve, and at least 1,000 free inodes. These are conservative estimates, not disk reservations; another process consuming space can still cause safe failure.
3. Back up app/env, stop **only** `kingfisher-kingfisher-1`, verify no running writer/no host port/same volume. Independently prove all 17 fixed active SQLite databases, integrity, schema19, each episode body digest, IDs/body/document aggregate, all stored table rows, settings/background bytes and pause. Cold copy the **entire** `/data`, including arbitrary auxiliary files, existing backups and operational `recovery-status.sqlite3`. Compare full recursive tree and logical inventory to the stopped source; save a private file manifest. Reject WAL/SHM/journal leftovers; never delete/checkpoint them. Recheck source unchanged before migration.
4. Run the frozen preflight only in the new image, same named volume RW, network none, no ports/restart, Python entrypoint, explicit `--service-stopped --unpublished`. Data-proof containers mount the volume read-only. Compare process/actual container exit codes; parse one JSON object. During migration a polling guard allows only that exact migration container as writer and repeats native/LaunchAgent/Compose/port/volume checks.
5. `migrated` requires exit0, exact patch identity, verified snapshot, empty outdated list, publish permission, and a separate fresh schema20 proof with every original/table/settings/background unchanged except the known nullable NULL column. Missing/malformed/contradictory result, a nonzero success exit, failed recovery or lost maintenance window never publishes or starts the old app.
6. A correctly reported `preflight_failed` may restart the unchanged old container only after an independent unchanged schema19 inventory and absent inspection marker. `restored_inspection` additionally requires verified rollback and independently proved schema19 plus inspection marker; the old image is started only for inspection, and both health and recovery route must report inspection/non-operational. The orchestrator itself has **no restore/downgrade action**.
7. After all success proofs, atomically replace only the image line; Compose uses `up -d --no-build --pull never`. The `published` result flag marks entry into this possibly-exposed boundary before Compose returns. Any failure here is `forward_repair_required`: leave the new image/config and current data, never restore historical data or start the old image. Success requires new version/health, read-only world route, visible intake pause/no active reads, exact same volume/new image, fresh 17-DB integrity and original/body/source/settings/background preservation, unchanged native bundle and env. It does not claim a native UI interaction test.

## Boundaries that matter

- **The watchdog is observation, not an atomic OS lock.** The operator must keep the native app closed and refrain from other Docker/Compose/writer actions until the installer finishes. A launch between observations can race the check. Detected violations fail closed for later phases; they do not undo a competing writer's actions. No unrelated process or LaunchAgent is stopped, and no universal exclusivity is claimed. On a timed-out attached Docker client, the migration container can still be running; the tool refuses publication and leaves it for manual inspection instead of killing it mid-migration.
- The cold copy covers all files. The product's verified migration snapshot covers only its fixed 16 SQLite stores plus two auxiliary allowlist files; the 17th `recovery-status.sqlite3` is separately proved and cold-copied, not falsely counted as part of that restore set.
- Pre/postpublish originals are required to match exactly in this paused maintenance window. A legitimate concurrent new input can cause conservative `forward_repair_required`; it is never deleted or rewound. Live database proof uses read-only SQLite transactions and respects WAL; only stopped proof requires absent sidecars.
- Results and caught errors expose closed codes, counts, hashes and fixed names, not tokens, original bodies, episode IDs or settings values. Private backups/file manifests may contain the full original files and names and sit under a newly created mode0700 directory; sensitive metadata/result files are mode0600.
- The reusable helper was not live-executed by its author. Product test/build/native-flow evidence and Root's actual installation, if performed later, must be reported separately. No claim of general rollback, future-schema support or semantic memory correctness follows from these tests.
