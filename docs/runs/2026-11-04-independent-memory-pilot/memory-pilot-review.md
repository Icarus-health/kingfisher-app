**Spec verdict: changes required. Code quality verdict: changes required.** Three Important findings; no Critical finding. The offline preview is usable for preparation, but the current wrapper should not be used for a paid pilot.

1. **Important — the requested elapsed limit can already be exceeded before the first HTTP request.** `scripts/probe_mistral_memory_pilot.py:131–155,181–195` starts the displayed timer before intake, but constructs the actual deadline afterward in `scripts/probe_mistral_source_package.py:108–110`. Mock clock reproduction: advance 601 seconds in real synthetic intake; with `max_seconds=600` the runner still dispatches one metadata GET and one inference POST, reporting 601.0 seconds. In addition, the inherited transport's I/O phase timeout and response-chunk checks (`scripts/probe_mistral_source_package.py:64–71,95–101`) cannot interrupt a blocked phase or force the unconditional worker join to return at the deadline. Use a single absolute monotonic deadline from run entry, including preparation; close admission after it, and bound waiting/cleanup at the hard wall time. Preserve an explicit unknown/held accounting receipt for an in-flight request if it cannot be joined within the budget. Test both exhausted preparation (zero dispatches) and a transport blocked past the cutoff.

2. **Important — changed frozen mail metadata can reach the model and still be reported as unchanged.** `scripts/probe_mistral_memory_pilot.py:102–107` compares only the Message-ID-derived key and stripped body before `:154` snapshots the resulting episode as the integrity baseline. Mocking the artificial IMAP transport to substitute only P01's sender kept the body and ID intact; the synthetic substitute address appeared in an outgoing task prompt, 31 mock inference POSTs ran, and the report returned `execution_complete` and `originals_unchanged=true`. A separate subject substitution was also accepted and reported unchanged. Validate a complete canonical projection against the frozen sources before taking the baseline (e.g. subject, body with only explicitly required RFC822 normalization, occurred-at, sender/recipient roles and owner, direction/folder, identity and any source linkage used), reject extras and drift before any GET/POST, and test metadata-only corruption.

3. **Important — a stopped run can discard the accounting and integrity receipt it is supposed to provide.** `scripts/probe_mistral_memory_pilot.py:191–218` tries to recompute a plan and dereference all original rows before reporting request counters and reading the temporary ledger. Mocking deletion of P01 during the first POST stopped dispatch at one POST, but the evaluator raised `EpisodeError` out of `finally`; `:256–257` would retain only its class name and drop the held/spent/request facts, while the temporary ledger is removed. Derive the plan from the immutable preflight snapshot, explicitly report missing/changed rows, and record accounting independently of result extraction. If a receipt field cannot be read, mark it unavailable and keep the independently known counters and reconciliation state. Test removal during the first dispatched inference request.

What checked out: default mode constructs no provider and reads no credential; the CLI requires a paid flag, affirmative synthetic cloud flag, an explicit positive at-most-$1 cap and the dedicated key before starting. Fixture manifest and all listed frozen file bytes are checked; only source JSON is parsed and the encoder maps individual input fields, so semantic gold is not sent. The ten-ID preview binds `include_tasks=True` and uses the real classification, categories and task jobs; there is no fallback provider, redirect or SDK retry, and GET plus POST admission stays within the configured total. The existing ledger stops on ambiguous billing and the credential guard rechecks the key and originals. The artifact labels semantic quality as requiring review, questions as not run, and records no automatically executed task in the exercised path. For independent source-quality review it would also help to export the saved classification reference kinds and spans from `jobs.memory.source_refs`; the current result has only classification state alongside categories/persons and the saved task/deadline proposals.
