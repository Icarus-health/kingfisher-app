# Kingfisher Product & Visual Design System

**Status:** Visual Foundation — Round 1  
**Authority:** Canonical design specification for Kingfisher  
**Rule:** Approved visual assets override generated or reconstructed alternatives.

## 1. Product character

Kingfisher should feel like returning home to an organised, alert counterpart: calm, personal, intelligent, premium, visually rich, and highly contextual. It must not look like a generic AI dashboard, a sterile enterprise admin interface, or a playful chatbot product.

The interface behaves like a chief of staff, but the product vision is broader: Kingfisher is the visual control surface for the user's digital life.

## 2. Core design principles

### 2.1 Visual before technical

Daily-use surfaces should expose people, priorities, projects, conversations, time, and decisions—not provider names, databases, API configuration, or model jargon.

### 2.2 Curated density

Kingfisher is information-dense but edited. The system should communicate: “many things happened; these few matter.” Avoid walls of equal cards and undifferentiated feeds.

### 2.3 Recognisable identity

The kingfisher bird is a product language, not decorative branding. Bird posture and motion communicate system state.

### 2.4 Context over channel

A person, project, decision, or task is primary. Gmail, WhatsApp, Slack, LinkedIn, calendar, documents, and news are secondary source channels.

### 2.5 Visual continuity

The same person image, project identity, status language, icon, and semantic color must persist across conversation, memory, tasks, calendar, briefing, and search.

## 3. Kingfisher state language

The canonical bird will be produced as controlled assets. Coding agents must never draw or generate substitutes.

- **Beobachten / Observing** — perched, calm, alert. Meaning: overview, monitoring, no immediate action.
- **Aktiv / Active** — controlled flight. Meaning: work is underway, orchestration, movement.
- **Tauchen / Diving** — diving posture. Meaning: deep research, focused analysis, retrieval.
- **Auftauchen / Surfacing** — rising from water. Meaning: result found, insight emerging.
- **Klarheit / Clarity** — bird plus information fragments organising into structure. Meaning: synthesis, decision support, understanding.
- **Ruhe / Rest** — settled posture with reduced visual energy. Meaning: nothing urgent, system at rest.

The bird is never used as a chatty mascot. No speech bubbles, anthropomorphic gestures, cartoon expressions, costumes, or novelty poses.

## 4. Color philosophy

Kingfisher uses a restrained palette derived from the bird and its environment.

- Deep Navy — primary structural background and dark-mode foundation
- Petrol — secondary structural surface
- Kingfisher Blue — active brand color and selected state
- Water Teal — connective, informational, memory and timeline language
- Copper / Orange — attention, energy, selected urgency; always sparse
- Warm White — primary light-mode field
- Stone — subdued neutral surface and border language
- Natural Green — limited semantic support, especially success/completion

Orange must never become a large background field in ordinary UI.

## 5. Typography philosophy

Kingfisher combines:

- an editorial serif for large human-facing moments: greetings, briefings, major headings, insight statements;
- a highly legible sans-serif for navigation, controls, lists, tables, metadata, messages, and dense information surfaces.

The contrast is intentional: serif = interpretation and human context; sans-serif = system structure and operation.

## 6. Iconography

Two layers exist:

### 6.1 System icons

Calendar, search, settings, mail, chevrons, download, attachment, filters, plus/minus, status utilities, playback, etc. come from one fixed professional SVG icon family. They are never generated by AI.

### 6.2 Kingfisher-specific semantic icons

Custom assets for memory, orchestration, research, insight, activity state, contextual relevance, and other distinctive concepts are maintained in this repository.

All icons must share optical size, stroke logic, corner character, and state treatment.

## 7. People and avatars

People are visually important entities in Kingfisher.

Image precedence:

1. Contact image provided by an authorised connected source, where permitted
2. Existing Kingfisher person image
3. User-uploaded image
4. Initials fallback

Never generate a replacement face for a real person.

A person entity owns one canonical image reference. The same image should appear everywhere that person is surfaced.

## 8. Memory graph

The graph represents relationships between people, projects, topics, decisions, documents, conversations, organisations, and places.

It should feel navigable and curated—not like a giant colourful knowledge-graph demonstration. Default views prioritise nearby relevant relationships; depth is progressively disclosed.

## 9. Motion

Motion communicates understanding and state.

Preferred motion language:

- breathing shifts rather than bouncing
- slow illumination changes
- relationships softly appearing
- calm focus transitions
- bird motion only when meaningful
- geometric fragments organising into clarity

Avoid decorative particle systems, neon AI glows, excessive shimmer, spinning loaders, and playful physics.

## 10. Asset authority

Implementation priority:

1. approved asset
2. approved component or token
3. approved system icon family
4. documented fallback

Generating a new visual is not an acceptable fallback when an approved asset exists.

## 11. Current scope

This document currently governs **Round 1: Visual Foundation**. Component specifications, screen anatomy, responsive rules, and interaction patterns will be added in later approved rounds.
